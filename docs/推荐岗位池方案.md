# 推荐岗位池（半自动采集）实施方案

> 前提：只采集用户**当前已打开、已登录、已渲染**的招聘网站搜索页；不自动翻页、不后台定时抓取、不绕过验证码或登录限制。
> 目标：用户点一次扩展按钮，把当前页职位卡片带进应用，按简历匹配度排序、去重，并决定「加入待投 / 忽略」。

## 1. 范围

### 做

- 扩展在招聘站搜索结果页提供「采集本页职位」按钮；
- 解析当前可见的职位卡片：岗位名、公司、城市、薪资、标签、详情链接、列表里的短描述；
- 通过现有 `jobBridge` 发到应用；
- 应用新增「推荐岗位池」：按匹配度排序、去重、加入待投、忽略、打开原页；
- 本地匹配复用 `analyzeJd`；没有 AI Key 也能用。

### 不做（本期）

- 服务端爬虫 / 代理池 / 无头浏览器批量抓取；
- 自动翻页、滚动加载全部、定时采集；
- 绕过登录、验证码、风控；
- 抓取详情页全文（列表页拿不到完整 JD 时，用户点「打开原页」用现有详情桥补充）；
- AI 自动筛选/爬取（AI 只做解释，且放在二期）。

## 2. 用户流程

1. 应用「职位推荐」页点「去搜索」，打开 BOSS/拉勾/猎聘搜索页（已登录）。
2. 扩展在页面右下角注入浮动按钮「采集本页职位（N）」，或在扩展弹窗点「采集当前页」。
3. 扩展解析当前 DOM 中可见的卡片，最多 40 条；先在按钮/弹窗里显示数量。
4. 点击后通过 `background` → `content-app` → `window.postMessage` 发到应用。
5. 应用收到后切到「职位推荐 → 推荐岗位池」，Toast「已采集 18 个岗位」。
6. 列表按匹配分排序；每行可「加入待投 / 忽略 / 打开原页 / 复制链接」。
7. 用户手动翻页后再点一次采集；新岗位与已有池合并、去重。

## 3. 数据模型

新增 `src/lib/jobPool.ts`：

```ts
export type JobPoolSource = "boss" | "lagou" | "liepin" | "zhaopin" | "51job" | "other";

export type PoolJob = {
  id: string;            // 去重键的 hash / 直接存 key
  key: string;           // canonical URL 或 company|role|city
  company: string;
  role: string;
  city: string;
  salary: string;
  tags: string[];
  url: string;           // http(s) only
  source: JobPoolSource;
  jdPreview: string;     // 列表卡片能拿到的短描述，≤ 2000 字
  state: "new" | "queued" | "ignored";
  applicationId?: string; // 加入待投后写入
  capturedAt: number;
};
```

约束：

- 存储 key：`resume-workshop:job-pool:v1`；
- 总量上限 300 条，超出丢弃最旧的 `new`，`queued` 不丢；
- 文本上限：公司/岗位 100、城市/薪资 50、标签 8 个 × 30 字、JD 预览 2000、URL 1000；
- 复用 `preserveUnreadable` 做损坏数据备份；
- 事件：`resume-workshop:job-pool-change`，跨标签页用 `storage` 事件同步。

匹配分不落盘，渲染时 `analyzeJd(jdPreview + " " + tags.join(" "), resume)` 现算：

- `keywordCount > 0`：显示分数与「已覆盖 / 还差」；
- `keywordCount === 0`：显示「信息不足」，提示打开原页查看详情，不强行给 0 分排序（排在最后）。

## 4. 扩展端

### 4.1 列表解析

新增 `extension/content-list.js`，或在 `content-job.js` 里增加 list 模式。建议独立文件，避免影响详情页提取。

站点规则（先做 BOSS，其余 best-effort）：

| 站点 | 卡片容器 | 字段候选 |
|---|---|---|
| BOSS | `.job-list-box .job-card-wrapper`、`.job-card-box` | `.job-name` / `.company-name` / `.job-area` / `.salary` / `.tag-list li` / `a` href |
| 拉勾 | `.positionListItem`、`[data-index]`（类名会变，先多候选） | `.positionLink` / `.companyName` / `.jobCity` / `.salary` / `.labels` |
| 猎聘 | `.job-list-item` | `.job-title-box` / `.company-name` / `.job-salary` / `.job-labels-box span` / `a` |
| 智联 | `.joblist-box__item` | `.iteminfo__line1__jobname` / `.iteminfo__line1__compname` / `.iteminfo__line2__jobdesc__salary` / `.iteminfo__line2__jobdesc span` |
| 前程无忧 | `.j_joblist .e` | `.jname` / `.cname` / `.sal` / `.tags span` / `a` |

规则：

- 只取 `getBoundingClientRect()` 在视口内、且没有 `display:none` 的卡片；
- 单次最多 40 条；解析失败的单条跳过，不阻塞整页；
- URL 用 `new URL(href, location.href).href`，只接受 http(s)；
- 去重键见第 6 节；
- 页面没有识别到卡片时，按钮显示「未识别到职位卡片」，并提示「确认在搜索结果页」。

### 4.2 入口

两种入口都做，共用 `collectCurrentPage()`：

- 浮动按钮：右下角固定 `z-index`，文案「采集本页职位（N）」，只在 `content-list.js` 匹配的搜索页显示；
- 扩展弹窗：新增「采集当前页」按钮，点击后向当前 tab 发 `collect-list` 消息，结果回显数量。

### 4.3 消息链路

```
content-list.js
  chrome.runtime.sendMessage({ type: "job-list", jobs })
background.js
  findAppTab(appUrl) / 必要时打开应用
  chrome.tabs.sendMessage(appTab.id, { type: "job-list", jobs })
content-app.js
  window.postMessage({ source: "resume-workshop-extension", type: "job-list", payload: { jobs } }, origin)
```

`background.js` 复用现有 `DELIVER_ATTEMPTS` 重试；失败时弹窗/按钮提示「没能连上简历工坊页面」。

### 4.4 manifest

- `content-list.js` 的 matches 与详情页一致（5 个招聘站）；
- 不新增权限；仍用 `storage` + `tabs`；
- 扩展说明与 README 写明「只读当前可见页面」。

## 5. 应用端桥接

修改 `src/lib/jobBridge.ts`：

- 新增 `type: "job-list"` 分支；
- `parseBridgeJobs(payload)`：
  - 数组、长度 ≤ 50；
  - 每条按字段白名单收敛、长度截断；
  - URL 必须 http(s)，拒绝 `javascript:` / `data:`；
  - `source` 只允许枚举值，未知归 `other`；
  - 丢弃 `role` 和 `company` 都为空的条目；
- 与现有单条 `lead` 共用 `pending` 队列和 listener，消息结构区分 `type`；
- 订阅者取走时区分 lead / list（或分两个队列）。

`content-app.js` 增加：收到 `job-list` 时转发同源 `postMessage`。

## 6. 去重

两级键：

1. 有 URL：规范化 URL（小写 host、去 hash、删 `utm_*` / `from` / `source` / `securityId` / `lid` 等跟踪参数、保留 pathname 与必要 query）；
2. 没有 URL：`company|role|city` 小写去空白。

入库时：

- 已存在同 key：合并缺失字段（薪资、标签、jdPreview 取更长），保留原 state；
- 同一批消息内也去重；
- 300 条上限，优先保留 `queued`，其次新的 `new`。

## 7. 应用端 UI

新增 `src/components/jobs/JobPoolPanel.tsx`，挂到 `JobsPanel` 的「匹配结果」与「待投清单」之间，并加入页内导航。

结构：

- 标题：「推荐岗位池」+ 数量 + 「已采集」时间；
- 筛选：全部 / 未处理 / 已忽略 / 已加入待投；排序：匹配度 / 最新；
- 空状态：说明如何用扩展采集 + 「去搜索」按钮（复用 `JOB_BOARDS` 链接）；
- 行：分数徽标、公司·岗位、城市/薪资、标签、缺口技能、来源 badge、采集时间；
- 操作：
  - **加入待投**：创建 `JobApplication`（status `wishlist`，company/role/city/jdPreview），保存后把池条目标 `queued` + `applicationId`；
  - **忽略**：标记 `ignored`，8 秒内可撤销（Toast）；
  - **打开原页**：`target="_blank" rel="noopener noreferrer"`；
  - **复制链接**：`navigator.clipboard`，失败时降级提示；
- 行内提示：「岗位信息来自你采集时的页面，可能已过期，以原站为准」；
- 390px 下操作换行、不横向溢出。

AppShell：

- `installJobBridge` 的订阅回调目前只 `setTab("jobs")`；需要读取 pending list 并写入 jobPool（或由 `JobPoolPanel` 自己订阅并 `takePendingLists()`）；
- Toast：「已采集 N 个岗位」；
- 推荐池状态变化时更新数量 badge（可选）。

## 8. 状态与联动

- `new` → `queued`：加入待投成功后；
- `new` → `ignored`：忽略；可撤销回 `new`；
- `queued` 的岗位如果对应 application 状态变为 `applied`/`interview` 等，池行显示「已投」并禁止重复加入；
- 删除投递记录时，对应池条目标回 `new`（按 applicationId 反查）；
- 通过「当前 JD / 求职信 / Agent」处理的仍是 `JobApplication`，推荐池不另建一套流程。

## 9. AI 的角色（二期）

本期不接 AI。二期再加：

- 新接口 `POST /api/ai/jobs`：输入一条池岗位（公司/岗位/标签/短描述）+ 简历摘要，输出 1–2 句匹配原因与关键词；
- 复用现有同源校验、限流、64KB body 上限、超时与错误码；
- 结果只放内存/池条目可选字段，缓存按 key；不落 AI 原文；
- 明确 AI 不参与爬取与筛选决策，只做解释。

## 11. 测试

### 单元

- `parseBridgeJobs`：合法/超长/非数组/非法 URL/空岗位/未知 source；
- 去重键：URL 跟踪参数、大小写、company|role|city；
- 存储：300 上限、合并缺失字段、损坏数据备份、跨标签页事件（如果抽 hook）。

### 扩展 fixture QA

- BOSS 列表页 HTML fixture：卡片数量、字段、URL；
- 拉勾/猎聘/智联/51job 各一份 fixture，至少验证不抛异常、能命中主要字段；
- 点击「采集本页」后，断言 `job-list` 消息的条数与字段。

### 应用 QA

- 用 `window.postMessage` 模拟 `job-list`：池出现 N 条、排序正确；
- 重复采集：数量不增加（去重）；
- 加入待投：待投清单 +1，池条目变「已加入」；
- 忽略 + 撤销；
- 筛选/排序；
- 390px 无横向溢出、无控制台错误；
- 不影响现有详情页 `lead` 流程。

## 13. 验收标准

- 在 BOSS 搜索结果页点「采集本页职位」，2 秒内应用出现对应岗位；
- 匹配分按当前简历排序，重复采集不增加重复项；
- 「加入待投」后待投清单出现该岗位，池条目标记已加入；
- 「忽略」可撤销；
- 扩展只读当前可见 DOM，不产生额外自动请求；
- 无 AI Key 也能完成以上流程；
- 现有详情页 JD 桥接、QA 全部不回归。
