# 演示视频脚本（5–8 分钟）

> 目标：按大赛要求覆盖「项目介绍 / 核心功能演示 / AI 技术亮点」，普通话讲解，MP4、1080p。
> 建议总时长 7 分 20 秒。录制前清空个人书签与无关标签页，只保留演示用数据。

## 录制准备

- 分辨率 1920×1080，浏览器缩放 100%，隐藏书签栏里的私人内容；
- 使用「演示场景」数据（6 个岗位），不要展示真实姓名 / 手机号 / 邮箱；
- 不展示 `.env.local` 或任何 API Key；AI 区段可提前配置好 Key，若网络不稳就录「本地降级」路径；
- 提前打开：首页、职位推荐页、AI 工作台、采集书签说明页；
- 录屏软件：OBS / Windows 游戏录制 / QuickTime，麦克风单独测试。

## 分镜与口播

### 0:00–0:35 开场：一个问题

画面：首页首屏（SSR 标题 + 纸面预览）缓慢下移。

口播：
> 投简历最难的不是排版，而是三件事：这个岗位到底要什么、我的简历差在哪、投完以后怎么跟。
> 简历工坊把「看懂 JD → 判断匹配 → 定向修改 → 准备材料 → 记录投递」串成一条链路，数据只保存在你自己的浏览器里。

### 0:35–1:20 项目介绍与整体结构

画面：顶栏三个一级页面（编辑简历 / 职位推荐 / AI 工作台）依次切换。

口播：
> 产品分三块：编辑简历负责内容和排版；职位推荐负责匹配与投递管理；AI 工作台把求职 Agent 的步骤、工具调用和结果放在一个可观察的界面里。
> 前端是 Next.js 16 + React 19，首屏由服务端直接输出真实内容；AI 请求走同域 Route，API Key 只存在服务端。

### 1:20–2:35 核心功能一：编辑、模板与交付

画面：编辑页左侧填一段简介，右侧实时预览；切换「侧栏」模板；打开「打印 / PDF」看分页。

口播：
> 左侧表单、右侧 A4 实时预览；8 套模板、字体搭配、中英双语、手动分页与页码。
> 交付不只 PDF：可以导出 Word、图片版 PDF、ATS 纯文本；双栏模板打印时会改成浮动侧栏，保证正文能正常跨页。

### 2:35–3:40 核心功能二：可解释的匹配

画面：职位推荐页点「演示场景」，出现 6 个岗位，分数从高到低；展开一个岗位的核心要求与缺口。

口播：
> 匹配分不是黑盒：核心要求 55、加分技能 20、简历完整度 25，逐项展示。
> 核心要求按同族技能分组，只会 React 也算满足前端框架要求；缺口会告诉你可以补什么，点一下就能写进简历。

### 3:40–4:50 核心功能三：无需插件的采集书签

画面：职位推荐页顶部的「采集当前页职位」；切到 BOSS 搜索结果页（打码个人信息），点书签；回到应用点「粘贴采集结果」，预览弹窗出现。

口播：
> 职位数据从哪来？不需要安装插件。职位页生成一个采集书签，在招聘网站搜索结果页点一下，书签只读当前页已渲染的卡片，把岗位名、公司、城市、薪资、标签复制到剪贴板；回到应用粘贴预览，再决定加入待投。
> BOSS 的薪资有字体反爬，我们按私有区字符规则还原成数字；不自动翻页、不后台抓取、不新开网页，也不绕过验证码。

### 4:50–6:20 AI 技术亮点：Agent + 事实核对 + 人工在环

画面：AI 工作台选一个岗位，启动工作流；前两步本地执行，第三步流式输出；事实核对标出素材外数字；点「采用并写入」后按 Ctrl+Z 撤销。

口播：
> AI 不是右上角一个按钮。Agent 先规划步骤，工具白名单校验后执行；本地步骤跑完会把观察回灌给模型重新规划。
> 模型只负责它擅长的两步：按 JD 改写、生成求职信；写完后本地做数字、技能、名称的事实核对，必须人工点「采用」才写入，而且写入进入撤销栈。
> 没有 Key、断网或输出不合规时，自动回退本地计划，核心流程仍然能演示。

### 6:20–7:00 测试、部署与隐私

画面：终端快速跑 `npm test`（可加速）；浏览器打开线上地址；展示「数据仅保存在本机」提示。

口播：
> 项目有 310 个单元 / 组件用例和完整浏览器 QA，覆盖打印、多标签页、离线缓存、采集书签和 Agent。
> 线上部署在 Vercel，地址公开、无需登录；简历和投递记录只存在 localStorage，AI 只收到必要字段，API Key 不进入前端和仓库。

### 7:00–7:20 收尾

画面：回到首页 / 作品名。

口播：
> 简历工坊想做的不是又一个排版工具，而是把求职里最耗神的判断和跟进，变成一条可解释、可撤销、数据留在本机的流程。谢谢观看。
