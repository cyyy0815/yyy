## 怎么跑起来

```bash
# 1. 安装依赖（Node.js 20+）
npm ci

# 2. 配置环境变量
cp .env.example .env.local
#    编辑 .env.local，填入 DEEPSEEK_API_KEY（不填也能跑，AI 步骤会降级）

# 3. 启动
npm run dev          # http://localhost:3000
```

生产模式：

```bash
npm run build && npm run start
```

## 怎么看

1. 打开首页 → 顶栏点****演示场景****，载入示例简历与 6 个目标岗位；
2. 在**待投清单**里点任意岗位的****准备****；
3. 点****启动求职 Agent****→**自动执行本地步骤**→ 第三步**执行**看流式改写与事实核对；
4. 顶栏**打印 / PDF**可看排版与分页；
5. 职位推荐页顶部**采集当前页职位**可生成书签，在 BOSS / 拉勾 / 猎聘等搜索结果页点书签，回到应用点**粘贴采集结果**。

> 数据存在浏览器本地，换设备或清缓存就是空的——这是隐私优先的设计，不是 bug。

## 自检与评测

```bash
npm test          # 310 个单元 / 组件用例
npm run eval      # 生成 docs/eval-report.md（离线评测：画像识别、分组收益、事实核对）
npm run qa        # 需要先 build + start，完整浏览器端到端 QA
npm run preflight # 推送公开仓库前的自检
```

## 采集书签（无需安装插件）

职位推荐页提供**采集本页职位**书签：拖到书签栏后，在招聘网站搜索结果页点一下，当前页岗位会复制到剪贴板；回到应用点**粘贴采集结果**预览，再选择加入待投清单。剪贴板被拒时可用**手动粘贴采集结果**。

不自动翻页、不后台定时抓取、不新开网页、不绕过验证码；旧版 Chrome 扩展保留在 `源码/extension/`，仅作兼容，不再是主路径。
