# 简历工坊 · 离线评测报告

> 由 `npm run eval` 生成，数据全部来自仓库内的岗位画像库与手写样本，可复现。

## 1. 岗位画像识别

用 26 个岗位画像各自的「核心 + 加分」技能构造简历，检查能否认回同一个画像。

- 识别正确：**26 / 26**（100%）

## 2. JD 覆盖率（上界）

用画像生成对应的 JD 文本，与「技能齐全」的同画像简历比对。这是**上界**：两边同源，只说明口径一致，不代表真实 JD 上的表现（见第 4 节的真实文案）。

- 平均覆盖率：**85 / 100**（26 个画像）

## 3. 核心要求分组的效果

模拟「同族技能只会其中一种」（如只会 React、不会 Vue），比较两种计分口径：

| 口径 | 平均核心要求达成率 |
|---|---|
| 逐项技能（旧） | 82% |
| 分组（现用） | **100%** |

分组避免了 18 个百分点的系统性低估。

## 4. 手写 JD 检查

5 段按真实招聘文案写的 JD（非技能名堆砌），检查画像识别与缺口提示：

| 样本 | 期望画像 | 识别结果 | 提示的缺口 |
|---|---|---|---|
| 前端（React） | frontend | frontend | TypeScript / Webpack / Vite |
| Java 后端 | backend-java | backend-java | Spring Boot / 分布式 / 高并发 |
| 算法（推荐） | algorithm | algorithm | 深度学习 / TensorFlow / 推荐系统 |
| 产品经理 | product | product | PRD / 需求调研 |
| 运维 / SRE | devops | devops | Kubernetes / Terraform / Prometheus |

- 画像命中：**5 / 5**
- 给出具体缺口：**5 / 5**

## 5. AI 事实核对

对 20 条注入的「素材里没有的数字 / 技能」检查检出率，并用 5 条干净文本检查误报：

| 指标 | 结果 |
|---|---|
| 注入事实检出 | **20 / 20** |
| 干净文本误报 | 0 / 5 |

## 局限

- 样本由画像库自动构造 + 5 段手写 JD，规模小，不代表公开基准；
- 第 1、2 节的简历由画像生成，存在循环性，第 4 节用手写文案缓解；
- 事实核对只做字面比对，同义改写、跨语言表达可能漏报，也不判断内容是否正确。
